\section{Detailed Infrastructure Architecture for 10,000 Users}
% =========================================================================

\subsection{Pro Rooms: Real-Time Audio Spaces Infrastructure}
To support live audio rooms where analysts, executives, and retail traders speak and listen concurrently:
\begin{enumerate}
    \item \textbf{WebRTC SFU Architecture:}
    Standard peer-to-peer (mesh) WebRTC fails beyond 4--5 participants. An enterprise SFU (Selective Forwarding Unit) receives a single audio stream from each active speaker and fans it out over optimized edge relays to hundreds or thousands of listeners.
    \item \textbf{Technology Recommendation: LiveKit Cloud or Agora Audio Engine:}
    \begin{itemize}
        \item \textit{Option A (LiveKit Cloud - Recommended):} Open-source WebRTC standard with dedicated global edge infrastructure, built-in speaker/listener roles, mute management, and automatic recording egress.
        \item \textit{Option B (Self-Hosted LiveKit on AWS EC2):} Running LiveKit SFU on an AWS \texttt{c6i.xlarge} instance reduces bandwidth costs significantly if DevOps bandwidth is available.
    \end{itemize}
    \item \textbf{Audio Spaces Capacity Model:}
    \begin{itemize}
        \item Active speakers per room: 3--6 participants ($\sim$64 kbps Opus audio).
        \item Passive listeners per room: 100--400 participants ($\sim$48 kbps Opus audio).
        \item Average session duration: 60 minutes.
        \item Monthly volume: $\approx$ 1,000,000 participant audio minutes.
    \end{itemize}
\end{enumerate}

\subsection{Multimedia Pipeline: Public Feed \& End-to-End Private DMs}
\begin{enumerate}
    \item \textbf{Object Storage Layer (Cloudflare R2):}
    AWS S3 charges significant egress fees (\$0.09/GB). \textbf{Cloudflare R2 charges \$0.00 for data egress}, eliminating bandwidth shock. Storage is billed at a flat \$0.015/GB-month.
    \item \textbf{Direct Client Upload via Pre-signed URLs:}
    The client requests a secure upload ticket from the backend (\texttt{POST /api/media/presigned-url}). The backend generates a cryptographically signed PUT URL. The client uploads directly to R2, bypassing and protecting the Express API servers.
    \item \textbf{Public Media (Post Attachments):}
    Public images, chart screenshots, and video clips are cached and distributed globally through Cloudflare CDN with automated WebP/AVIF transformation.
    \item \textbf{Private DM Media Security:}
    Media shared in 1-on-1 direct messages is placed in a private, unlisted R2 bucket. Access is strictly mediated via time-limited signed URLs (valid for 15 minutes) issued only after verifying the user's membership in the target \texttt{Conversation}.
\end{enumerate}

\subsection{High-Performance Real-Time Streaming (SSE / WebSockets + Redis)}
\begin{enumerate}
    \item \textbf{Decommissioning Client Polling:} Replace the continuous \texttt{/api/live} HTTP requests with a persistent \textbf{Server-Sent Events (SSE)} or \textbf{WebSocket connection}.
    \item \textbf{Shared Redis Message Bus:} A managed Redis cluster (Upstash Redis or AWS ElastiCache) handles pub/sub events. When an author posts, a filing arrives, or a direct message is sent, a lightweight event packet is broadcasted to connected sockets in under 50 milliseconds.
    \item \textbf{Database Protection:} This reduces database read queries from 1,200 QPS to under 15 QPS during peak market hours.
\end{enumerate}

\section{Engineering Implementation Checklist to Reach Operations}
% =========================================================================

To transition the software from its present repository state to live production, the following engineering tasks must be executed:

\subsection{Sprint 1: Database \& Caching Hardening}
\begin{itemize}
    \item Deploy a Supabase Pro or AWS RDS PostgreSQL database with transaction connection pooling.
    \item Run all Prisma migrations (\texttt{npx prisma migrate deploy}) to generate production schema.
    \item Provision a managed Redis cluster and build an abstraction layer (\texttt{redis.ts}) for caching NGX market quotes and session states.
\end{itemize}

\subsection{Sprint 2: Media Storage \& Access Control Layer}
\begin{itemize}
    \item Create Cloudflare R2 buckets: \texttt{liquidity-square-public} and \texttt{liquidity-square-private-dm}.
    \item Implement backend endpoints \texttt{POST /api/media/upload-url} issuing presigned S3/R2 PUT signatures with MIME-type and 25MB file-size validation.
    \item Add \texttt{MediaAttachment} relations in Prisma schema to associate files with \texttt{Post} and \texttt{DirectMessage} records.
    \item Update frontend composer (\texttt{composer.tsx}) and DM thread ([`message-thread.tsx`](file:///c:/Users/nwaug/Desktop/liquidity-square-1/frontend/src/components/square/message-thread.tsx)) to render interactive photo galleries, video players, and audio wave previews.
\end{itemize}

\subsection{Sprint 3: Pro Rooms WebRTC Audio Spaces Integration}
\begin{itemize}
    \item Provision a LiveKit Cloud organization or deploy self-hosted LiveKit SFU instance.
    \item Create backend room token generation endpoint (\texttt{POST /api/rooms/:slug/token}) providing JWT tokens with participant role metadata (\textit{Host}, \textit{Speaker}, \textit{Listener}).
    \item Replace mock room layout in [`rooms/[slug]/page.tsx`](file:///c:/Users/nwaug/Desktop/liquidity-square-1/frontend/src/app/square/rooms/%5Bslug%5D/page.tsx) with LiveKit React Components (\texttt{@livekit/components-react}), featuring live speaker avatars, speaking indicators, hand-raising queues, and audio visualizers.
\end{itemize}

\subsection{Sprint 4: Market Telemetry Resiliency}
\begin{itemize}
    \item Decouple the NGX SharePoint scraper from client web requests. Establish a standalone Node.js cron worker that executes every 60 seconds during market hours, commits quotes to Redis, and broadcasts updates via SSE.
    \item Acquire production API credentials from NGN Market and configure automated weekly company profile synchronization.
\end{itemize}

\subsection{Sprint 5: Production Deployment \& CI/CD Pipeline}
\begin{itemize}
    \item Configure production environment variables in Vercel and container orchestration service.
    \item Route custom domain (\texttt{liquiditysquare.com} or \texttt{liquiditypro.com}) through Cloudflare with active SSL/TLS termination and DDoS mitigation rules.
    \item Configure Sentry performance tracing and set up uptime heartbeat alerts.
\end{itemize}
